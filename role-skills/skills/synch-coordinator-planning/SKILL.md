# Coordinator planning

1. Start from the accepted brief version. Map every acceptance criterion to a plan step and to the evidence that would satisfy it. Record dependencies so independent assignments can proceed concurrently through the daemon. A single specialist is enough when the task calls for one.
2. Request work through Synch. For each assignment, include its purpose, specialist role and reason for selection, input revision or target, permitted actions, dependencies, and expected evidence. Use the configured default eligible harness and model unless routing evidence supports another eligible pair. Honor the operator's pin. Surface an unavailable permitted pair for an operator decision.
3. Keep planning and evidence review within the Coordinator's role. The daemon dispatches work, evaluates policy, manages grants and approvals, and enforces limits. Route new targets, broader access, changed acceptance criteria, and higher operator-set limits to the operator. Respect Review plan first when selected. Action-specific approvals still apply.
4. When specialists disagree, pause the affected step and request a check that can resolve the disagreement. Continue independent work. Escalate unresolved material risk. If a harness fails, capture the checkpoint and wait for the operator's replacement choice. Reconcile pending external requests before resuming.
5. Reconcile each criterion against the delivered revision or target. Record check outcomes, audit status, and human acceptance as separate facts. Surface missing, stale, and inconclusive evidence. Request a correction when a criterion remains open.
